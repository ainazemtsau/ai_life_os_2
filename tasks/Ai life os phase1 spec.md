# AI Life OS — Спецификация Фазы 1 (v2)

## Обзор фазы

**Название:** Полноценный чат с админкой ассистентов

**Цель:** Создать базовую инфраструктуру с функционалом современных чат-ботов (ChatGPT, Claude) и административным интерфейсом для управления AI-ассистентами.

**Результат:** Работающее приложение, где можно создавать ассистентов, вести с ними разговоры, редактировать сообщения с ветвлением, и получать альтернативные ответы.

---

## Итерация 1.1: Базовый чат со streaming

### Описание
Минимальный работающий чат: пользователь отправляет сообщение, получает ответ от AI с эффектом печатания (streaming). Можно остановить генерацию.

### Функциональные требования

**Отправка сообщения**
- Текстовое поле для ввода сообщения
- Отправка по Enter (Shift+Enter — перенос строки)
- Отправка по клику на кнопку
- Поле ввода недоступно во время генерации ответа

**Streaming ответа**
- Ответ появляется посимвольно/потоком по мере генерации
- Визуальный индикатор что AI "печатает"
- Плавная прокрутка к новому контенту

**Остановка генерации**
- Кнопка "Stop" появляется во время генерации
- По клику генерация прерывается
- Частичный ответ сохраняется и отображается

**Отображение сообщений**
- Чёткое визуальное разделение сообщений пользователя и AI
- Аватары или иконки для идентификации
- Timestamp (опционально, можно показывать при hover)

**Scroll to Bottom**
- Кнопка "↓" появляется когда пользователь прокрутил вверх (>100px от низа)
- По клику — плавная прокрутка к последнему сообщению
- Во время генерации автоматическая прокрутка к новому контенту
- Если пользователь прокрутил вверх во время генерации — автопрокрутка отключается

**Unread Indicator**
- Если вкладка неактивна и генерация завершилась — индикатор в title вкладки ("● AI Life OS")
- При возврате на вкладку — title восстанавливается

### Acceptance Criteria
- [ ] Пользователь может ввести текст и отправить сообщение
- [ ] Ответ AI появляется постепенно (streaming)
- [ ] Во время генерации отображается индикатор
- [ ] Кнопка Stop останавливает генерацию
- [ ] После остановки частичный ответ виден
- [ ] Сообщения визуально различаются (user vs assistant)
- [ ] Кнопка scroll-to-bottom появляется при прокрутке вверх
- [ ] Клик на кнопку прокручивает к последнему сообщению
- [ ] Автопрокрутка во время генерации
- [ ] Автопрокрутка отключается если пользователь прокрутил вручную
- [ ] При завершении генерации в неактивной вкладке — индикатор в title
- [ ] При активации вкладки индикатор убирается

## Итерация 1.2: Персистентность и threads

### Описание
Сообщения сохраняются в базе данных. Пользователь может иметь несколько разговоров, переключаться между ними, создавать новые и удалять существующие.

### Функциональные требования

**Сохранение сообщений**
- Каждое сообщение сохраняется в БД
- При перезагрузке страницы история восстанавливается
- Сохраняется: текст, роль (user/assistant), timestamp, связь с разговором

**Список разговоров (threads)**
- Боковая панель со списком всех разговоров
- Отображается название разговора
- Сортировка по дате последнего сообщения (новые сверху)
- Индикатор текущего активного разговора

**Автогенерация заголовков**
- Заголовок = первые 50 символов первого сообщения пользователя
- Обрезается по слову + "..." если длиннее
- Генерируется сразу при отправке первого сообщения

**Создание разговора**
- Кнопка "New chat" / "+"
- При создании разговор сразу становится активным
- Пустой разговор удаляется если не было сообщений

**Переключение между разговорами**
- Клик на разговор в списке загружает его историю
- Текущий разговор подсвечивается в списке
- При переключении незаконченная генерация прерывается

**Удаление разговора**
- Кнопка удаления (иконка корзины или через меню)
- Подтверждение перед удалением
- После удаления переключение на следующий разговор или пустой экран

**Empty States**
- При отсутствии разговоров: центрированное сообщение "Начните новый разговор" + кнопка "New Chat"
- Новый пустой разговор: приветственное сообщение от ассистента (имя + "Чем могу помочь?"), фокус на поле ввода

### Acceptance Criteria
- [ ] Сообщения сохраняются и загружаются при перезагрузке
- [ ] Боковая панель показывает список разговоров
- [ ] Заголовок разговора — первые 50 символов первого сообщения
- [ ] Если сообщение длиннее, обрезается по слову и добавляется "..."
- [ ] Можно создать новый разговор
- [ ] Можно переключаться между разговорами
- [ ] Можно удалить разговор с подтверждением
- [ ] Пустые разговоры автоматически удаляются
- [ ] При отсутствии разговоров показывается приглашение создать новый
- [ ] Новый разговор показывает приветствие ассистента

## Итерация 1.3: Редактирование и ветвление

### Описание
Пользователь может отредактировать своё сообщение. При редактировании создаётся новая ветка разговора, старая ветка сохраняется. Можно переключаться между ветками.

### Функциональные требования

**Модель данных: дерево сообщений**
- Каждое сообщение имеет parent_id (ссылка на предыдущее)
- Корневое сообщение имеет parent_id = null
- Ветка — это путь от корня до листа
- При редактировании создаётся новое сообщение с тем же parent_id

**Редактирование сообщения пользователя**
- Кнопка "Edit" на сообщении пользователя (при hover)
- Текст сообщения становится редактируемым
- Кнопки "Save" и "Cancel"
- При сохранении:
  - Создаётся новое сообщение (edited) с тем же parent_id
  - Запускается генерация нового ответа AI
  - Старая ветка сохраняется
  - Текущий вид переключается на новую ветку

**Навигация между ветками**
- Если у сообщения есть "соседи" (siblings), показывается навигатор
- Формат: "< 1/3 >" — текущая ветка из общего числа
- Стрелки переключают между ветками
- При переключении загружается вся ветка от этого сообщения до конца

**Визуальное представление**
- Отображается только текущая ветка (линейно)
- Навигатор веток показывается там, где есть разветвление
- Нет визуального дерева — только переключение

### Acceptance Criteria
- [ ] Кнопка Edit появляется на сообщениях пользователя
- [ ] При редактировании текст можно изменить
- [ ] После сохранения генерируется новый ответ
- [ ] Старая ветка сохраняется и доступна
- [ ] Навигатор "< 1/3 >" отображается где есть ветвление
- [ ] Можно переключаться между ветками стрелками
- [ ] При переключении вся ветка обновляется корректно

## Итерация 1.4: Регенерация и варианты

### Описание
Пользователь может запросить альтернативный ответ AI. Все варианты сохраняются, между ними можно переключаться.

### Функциональные требования

**Регенерация ответа**
- Кнопка "Regenerate" на последнем ответе AI
- По клику генерируется новый ответ
- Новый ответ становится "соседом" (sibling) текущего
- Текущий вид переключается на новый вариант

**Навигация между вариантами**
- Использует тот же механизм что и ветки
- Навигатор "< 1/3 >" на ответах AI с вариантами
- Можно листать между всеми вариантами

**Взаимодействие с ветвлением**
- Регенерация на не-последнем сообщении создаёт новую ветку
- Если пользователь продолжил разговор после варианта — это отдельная ветка

### Acceptance Criteria
- [ ] Кнопка Regenerate на последнем ответе AI
- [ ] Новый вариант генерируется и отображается
- [ ] Старый вариант сохраняется
- [ ] Можно переключаться между вариантами
- [ ] Счётчик показывает количество вариантов
- [ ] Продолжение разговора после варианта работает корректно

## Итерация 1.5: Копирование, форматирование и shortcuts

### Описание
Удобные действия для работы с ответами: копирование, рендеринг markdown, подсветка кода, клавиатурные сокращения.

### Функциональные требования

**Копирование**
- Кнопка "Copy" на каждом сообщении
- Копирует текст в буфер обмена
- Визуальный feedback (иконка меняется на галочку)
- Для кода: отдельная кнопка копирования на блоке кода

**Markdown рендеринг**
- Ответы AI рендерятся как markdown
- Поддержка: заголовки, списки, bold/italic, ссылки, цитаты
- Блоки кода с указанием языка

**Подсветка синтаксиса**
- Код в блоках подсвечивается по языку
- Название языка отображается в header блока
- Кнопка копирования кода в header блока

**Форматирование текста пользователя**
- Сообщения пользователя отображаются как plain text
- Переносы строк сохраняются

**Keyboard Shortcuts**

| Действие | Shortcut |
|----------|----------|
| Отправить сообщение | Enter |
| Новая строка | Shift + Enter |
| Остановить генерацию | Escape |
| Новый разговор | Ctrl/Cmd + Shift + O |
| Фокус на поле ввода | Ctrl/Cmd + / |
| Отмена редактирования | Escape |

### Acceptance Criteria
- [ ] Кнопка Copy копирует текст сообщения
- [ ] Визуальный feedback после копирования
- [ ] Markdown рендерится корректно (headers, lists, links)
- [ ] Блоки кода имеют подсветку синтаксиса
- [ ] Кнопка копирования на блоках кода
- [ ] Отображается язык кода в header блока
- [ ] Enter отправляет, Shift+Enter — перенос строки
- [ ] Escape останавливает генерацию
- [ ] Escape отменяет редактирование сообщения
- [ ] Ctrl/Cmd + Shift + O создаёт новый разговор
- [ ] Ctrl/Cmd + / фокусирует поле ввода

## Итерация 1.6: Админка ассистентов

### Описание
Административный интерфейс для создания и настройки AI-ассистентов. Каждый ассистент имеет свои параметры: модель, провайдер, системный промпт.

### Функциональные требования

**Default Assistant**
- При первом запуске создаётся дефолтный ассистент:
  - Name: "Assistant"
  - Model: gpt-4o-mini
  - System Prompt: "You are a helpful assistant."
  - Temperature: 1
  - Max Tokens: не задан (дефолт модели)
  - Status: active

**Список ассистентов**
- Отдельная страница/раздел "Assistants"
- Таблица или карточки всех ассистентов
- Отображается: имя, модель, статус (active/inactive)
- Кнопка создания нового ассистента

**Создание ассистента**
- Форма с полями:
  - Name (обязательное)
  - Description (опциональное)
  - Avatar/Icon (опциональное, можно выбрать из preset)
  - Provider (пока только OpenAI)
  - Model (выпадающий список: gpt-4o, gpt-4o-mini, gpt-4-turbo, gpt-3.5-turbo)
  - System Prompt (textarea)
  - Temperature (slider 0-2, default 1)
  - Max Tokens (число, опциональное)
  - Status (active/inactive)
- Валидация обязательных полей
- Сохранение в БД

**Редактирование ассистента**
- Открытие формы с заполненными данными
- Возможность изменить любое поле
- Сохранение изменений

**Удаление ассистента**
- Кнопка удаления
- Подтверждение
- Нельзя удалить если есть активные разговоры (или soft delete)

**Привязка разговора к ассистенту**
- При создании разговора выбирается ассистент (если несколько активных)
- Если один активный — используется автоматически без выбора
- Последний использованный ассистент становится дефолтом для следующего разговора
- В списке разговоров отображается имя/аватар ассистента

**Empty State для ассистентов**
- Если нет активных ассистентов: сообщение "Нет доступных ассистентов" + кнопка "Создать ассистента" → переход в админку

### Acceptance Criteria
- [ ] При первом запуске существует дефолтный ассистент "Assistant" (gpt-4o-mini)
- [ ] Страница со списком ассистентов
- [ ] Можно создать нового ассистента с заполнением формы
- [ ] Валидация: name обязательное, model обязательная
- [ ] Можно редактировать существующего ассистента
- [ ] Можно удалить ассистента (с подтверждением)
- [ ] При создании разговора выбирается ассистент (если несколько)
- [ ] Если один активный ассистент — разговор создаётся без выбора
- [ ] Последний использованный становится дефолтом
- [ ] Разговор использует параметры выбранного ассистента
- [ ] В UI разговора отображается имя/аватар ассистента
- [ ] Если нет активных ассистентов — кнопка создания с переходом в админку

## Контекстное окно

### Описание
Обработка длинных разговоров, превышающих лимит контекста модели.

### Функциональные требования

**Truncation стратегия**
- При превышении лимита контекста — удаляются самые старые сообщения
- System prompt всегда сохраняется
- Минимум последние 4 сообщения всегда включены (2 пары user-assistant)
- Пользователь не уведомляется (silent truncation)

### Acceptance Criteria
- [ ] Длинные разговоры не вызывают ошибок API
- [ ] System prompt всегда передаётся
- [ ] Контекст обрезается с начала, сохраняя последние сообщения

## Общие требования фазы

### UX/UI
- Responsive design (desktop first, но не ломается на mobile)
- Быстрая загрузка, нет визуальных "прыжков"
- Состояния загрузки везде где есть async операции
- Обработка ошибок с понятными сообщениями

### Производительность
- Streaming работает плавно
- Длинные разговоры (100+ сообщений) не тормозят
- Виртуализация списка сообщений если необходимо

### Надёжность
- Сообщения не теряются при обрыве соединения
- Retry механизм для failed requests
- Graceful degradation при проблемах с API

## Сущности данных

### User
```
- id: UUID
- email: string
- name: string
- created_at: timestamp
```

### Assistant
```
- id: UUID
- name: string (required)
- description: string (optional)
- avatar: string (optional)
- provider: enum [openai]
- model: string (required)
- system_prompt: text
- temperature: float (0-2, default 1)
- max_tokens: integer (optional)
- status: enum [active, inactive]
- created_at: timestamp
- updated_at: timestamp
```

### Conversation
```
- id: UUID
- user_id: FK → User
- assistant_id: FK → Assistant
- title: string (auto-generated)
- created_at: timestamp
- updated_at: timestamp
```

### Message
```
- id: UUID
- conversation_id: FK → Conversation
- parent_id: FK → Message (nullable, для ветвления)
- role: enum [user, assistant, system]
- content: text
- status: enum [pending, streaming, complete, error, stopped]
- created_at: timestamp
```

### UserPreferences
```
- id: UUID
- user_id: FK → User
- last_assistant_id: FK → Assistant (nullable)
- updated_at: timestamp
```
